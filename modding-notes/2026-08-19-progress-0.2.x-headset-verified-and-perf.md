# Progress — 0.2.x: head-look verified on hardware; performance work started

*(2026-08-18 → 2026-08-19)*

## Milestone 1 is verified in the headset

The SteamVR overlay path (0.2.3) now works on real hardware (Quest 3 via
Virtual Desktop → SteamVR): no flicker, responsive head-look, overlay framed
correctly at the full 1280x960 window. Four fixes got it there, all found and
verified during home-machine sessions:

1. **Overlay flicker** — root cause was per-frame `SetOverlayRaw`, which makes
   the compositor tear down and recreate the overlay texture on every call.
   Fixed with persistent double-buffered D3D11 textures on the HMD's adapter
   via `SetOverlayTexture`, with uploads gated on the frame latch's sequence
   number.
2. **Mirrored head-look** — yaw sign was inverted; negated in the camera hook.
3. **Zombie process on quit** — quitting left an unkillable `XIII.exe` wedged
   in the NVIDIA driver, holding the single-instance lock until reboot. Fixed
   by IAT-hooking `kernel32!ExitProcess` to stop the VR host threads before
   the OS terminates them.
4. **Overlay framing** — windowed XIII requests a desktop-sized D3D8
   backbuffer but renders only in the top-left corner. The proxy now clamps
   the requested backbuffer to the window client size on `CreateDevice` and
   `Reset`.

`v0.2.0-alpha` ("first headset build") is tagged and released on the public
mod repo.

## Performance work (0.2.4)

In-headset framerate was poor even on the strong home machine, so the
capture path got profiled and tuned (attacks 1 and 2 of the plan recorded in
the dev archive's `docs/STATUS.md`):

- **Profiling instrumentation**: every capture phase is QPC-timed and
  summarized in a single-line `[xiii-perf]` heartbeat every 5 s. A new
  `tools/odscap.ps1` (DBWIN listener) reads the telemetry without DebugView.
- **First profile (dev machine)**: the `CopyRects` GPU→CPU readback dominates
  at avg ~2.7 ms / max ~9.3 ms per capture — about 6x everything else
  combined. This confirms the original hypothesis; the pipeline stall, not
  the pixel work, is the cost.
- **Rate cap**: the whole readback (not just the overlay upload) is now
  limited by `[VR] CaptureMinIntervalMs` (default 11 ms ≈ 90 Hz, 0 =
  uncapped) instead of running at game fps.
- **Cold path when VR is off**: with no VR host enabled the capture is
  skipped entirely — non-VR players run the stock game. Verified on the dev
  machine (no readbacks, no heartbeat; debug BMP frames still captured).
- **`capture_core`**: new unit-tested static library (doctest, TDD) holding
  the pure logic — pixel decode with a memcpy fast path for 32-bit formats,
  a wrap-safe rate limiter, and per-phase timing stats. The per-frame
  multi-megabyte `malloc`/`free` became a reused buffer.

**Next:** collect `[xiii-perf]` lines during the next home headset session
(the staging build's `BUILD.md` says exactly what to grab). Those numbers
choose between the cheap fix (double-buffered readback: copy into surface A,
lock last frame's surface B — no stall, one frame of latency) and the full
GPU-only shared-surface path that removes the CPU round-trip entirely.

## Infrastructure

- New **private staging repo** (`XIII2003-vr-staging`): receives the current
  built `D3DDrv.dll` plus a `BUILD.md` (version, source commit, verification
  state) automatically after every update. It is the cross-machine handoff
  channel; work graduates to the public repos only after headset testing.
- Repos renamed to the standard scheme (`XIII2003-vr-modding-notes`,
  `XIII2003-vr-staging`); local clones and backups follow the new names.
- The CMake build had broken (a new source file was only added to
  `build.bat`); fixed, and both build routes now carry the same source list.
