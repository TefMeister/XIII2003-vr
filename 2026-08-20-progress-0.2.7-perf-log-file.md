# 2026-08-20 — 0.2.7: perf heartbeats log to a file

Small quality-of-life change to make headset-session data collection
effortless before tonight's home test: the `[xiii-perf]` heartbeat now also
appends, with a local timestamp, to `%TEMP%\xiii_capture\xiii_perf.log`, and
each run writes a session-header line recording the date, rate cap, and
pipeline mode. Collecting the numbers the perf work needs is now just "play,
then send the file" — no DebugView or `odscap.ps1` listener required.

Details:

- Gated `[VR] PerfLog` (default on), and only active when a VR host is
  enabled — with VR off, nothing is written.
- The file is opened and closed per write (one line every 5 s), so it is
  always flushed and safe to copy while the game is still running.
- `OutputDebugString` telemetry is unchanged; DBWIN listeners see the same
  lines as before.
- Desk-verified: a 30 s run produced the session header plus six timestamped
  heartbeat lines. All 5 unit-test suites green.

State: dev archive commit `8f38348`, staged as 0.2.7 (`c5bf756`). Staging's
BUILD.md now asks the home session for two short runs (default config, then
`PipelinedReadback=1`) and a focus-fix confirmation, with the log file as
the single artifact to send back.
